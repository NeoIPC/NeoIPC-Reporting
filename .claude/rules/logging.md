## Logging

The service derives the whole render's verbosity from its own effective .NET log level and feeds the R and Quarto child diagnostics back into `ILogger` (`ReportLogging`, `ReportLogDrain`, and the producers built on `ExternalProcessReportProducer`, such as `QuartoReportProducer`).

- **One dial, from the .NET level.** Each producer's `GetProcessStartInfo` maps `ReportLogging.EffectiveMinLevel`, the lowest level enabled across the render's category sub-tree, to the child controls: `NEOIPC_LOG_LEVEL` (`Trace→debug`, `Debug→verbose`, `Information→normal`, `Warning+→quiet`) drives the R `logger` namespaces, including neoipcr's DHIS2 query trace, which appears only at `verbose` and `debug`, and `NEOIPC_LOG_FILE` names the structured file the R side writes. Quarto's `--log-level` is derived too, but **floored at `info`** (`Trace` and `Debug→debug`, else `info`).
- **Why Quarto is floored at `info`.** Quarto re-emits every line of Pandoc's stderr, whatever its severity, as one of its own `INFO` records, so `--log-level warning` would drop Pandoc's warnings *and errors* before they reach the log file; at `info` the lines are captured, and the drain recovers each one's severity from its `[ERROR]`, `[WARNING]`, or `[INFO]` prefix. Quarto flattens the lualatex and knitr output the same way, but without a per-line prefix, so the drain recovers those **only on a failed render** (`exitCode != 0`), leaving a successful render's benign warnings alone. Benign engine output (the LuaHBTeX banner, R progress) carries no signal and stays on `.Quarto`, and the emitted text has its ANSI colour codes stripped.
- **LaTeX recovery is structural.** Quarto's `writeError` emits `error("compilation failed- …")`, then the extracted detail, then a `see …log` pointer, and the drain re-attributes that whole block to `.LaTeX`. It keys on that structure, not on the detail's text, so it catches any `findLatexError` shape: the `l.<n>` context, the fixed `No pages of output`, or the luaotfload-fallback guidance the image's pinned Quarto emits.
- **R recovery** takes knitr's red ANSI colouring plus an R error signal and is **level-agnostic**, matching knitr's errors at whatever level Quarto re-emits them. The **colour-independent** signals, knitr's untranslated `Quitting from` frame and the native-crash markers (`caught segfault`, `R is aborting now`), match without colour, so recovery survives `NO_COLOR` **and** a non-English `LC_ALL`; the localized signals ride the red gate: the rlang `! ` bullet (punctuation, so itself locale-proof) and base R's `Error:`. `Execution halted` matches without colour too, but, since R translates it, only under an English `LC_ALL`. The red gate holds only because `GetProcessStartInfo` **scrubs `NO_COLOR`** from the child's environment (Deno gates its colour on `!Deno.noColor`).
- **Drain on success and failure.** After the child exits, `DrainDiagnostics` re-emits the two structured files, the R `layout_json` file and, for Quarto, `quarto-log.json`, into `ILogger` on the **success** path too, so a successful render's DHIS2 query trace reaches the log as well. The files are complete only once the child exits, so the drain emits **two ordered blocks**, one per source: Quarto records carry no timestamp, so the Quarto and R blocks are not interleaved, and each keeps its own file's order.
- **Per-source categories.** Each render logs under `NeoIPC.Reporting.Render.<report>` (`<report>` being `Partner-Report`, `Reference-Report`, or `Validation-Report`): `.Quarto`, `.Pandoc`, `.LaTeX`, `.R.report`, `.R.common` (the toolkit's shared `common/` layer), and `.R.neoipcr`. R output arrives two ways: `DrainRLogAsync` attributes the **structured** `layout_json` records by their `ns` field, while the **raw knitr stderr** recovered from Quarto's stream lands on `.R.report`, since that stream does not carry the origin namespace. Each source has its own sub-logger, tuned through `Logging:LogLevel:NeoIPC.Reporting.Render.*` in **both directions**: at the default `Information`, a successful render emits Quarto and Pandoc progress, so quieten a source (`…<report>.Quarto` → `Warning`) or raise one (`…<report>.R.neoipcr` → `Debug` for the DHIS2 query trace). The child's verbosity follows the **minimum** level across the sub-tree, so raising one source makes the child *write* its finer records rather than only letting them pass at emit time. `appsettings.Development.json` sets the whole `NeoIPC.Reporting.Render` tree to `Debug`.
- **Correlation.** Each render opens a `RenderId` log scope (a Quarto render's workdir name), with a nested `ProcessId` scope once the child starts, so concurrent renders' drained entries stay attributable; `appsettings.json` enables the console's `IncludeScopes`, which puts the scopes in the output.
- **GDPR.** The DHIS2 query trace is **URL, HTTP status, and row count only, never a response body** (the boundary is neoipcr's `log_dhis2_request`); add no drain path that could emit a response body. The LaTeX and R recovery can promote engine output that quotes report content (a TeX `l.<n>` line echoes the typeset source; an R error can name a value) to `Error` on a dedicated channel. That does not widen the data-protection boundary: it is the promotion the Pandoc recovery also performs, it changes only the level and channel of records Quarto already emits verbatim on `.Quarto` at the default level, the audience is still the operator, who already holds the rendered report, and `log_dhis2_request` is untouched.
